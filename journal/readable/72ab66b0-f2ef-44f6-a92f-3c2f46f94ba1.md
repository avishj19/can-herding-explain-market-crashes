## Two bugs worth knowing about
1. **The "HOW TO READ" arrow came out as the text `B8`.** I wrote the arrow as the CSS code `\25B8`. Python saw the `\2` inside its own string as a special code and swapped it for a hidden character. So the browser never got the arrow, just the leftover text "5B8". The fix was to type the actual ▸ character.
2. **`test_app_reloads_site_modules_after_a_push` failed after my edit, even though nothing it tests had changed.** The test pretends a `git pull` happened by moving `explore.py`'s "last changed" time 60 seconds later. The app compares that time with when Python last made its compiled copy (the `.pyc` file). `explore.py` was last changed Nov 20, but its compiled copy was made today, so "Nov 20 + 60 seconds" still looks older and no reload happens. The test had only been passing because some other site file happened to be newer than its compiled copy. I changed the test to stamp the file with the current time, which is what a real `git pull` does. Then I recreated the exact condition that failed before, and the test passes.

## Bugs between the website and the engine files
I checked every function the pages call against the engine modules: none are missing. Two problems did turn up:

1. **Stale data after a file changes.** The site caches anything it reads from a file, but the cache only notices when the *code* changes, not the file. After a refit, the site would have kept running the model with the **old** settings. Meanwhile `numbers.json` showed the new results, so the pages would disagree with each other. The same applied to data downloads and caption edits. The cache key now includes each file's "last changed" time, so a changed file is read again.
2. **A module missing from the auto-reload list.** The site now uses `herding/calibrate.py` (and, after today's work, `politics.py` and `experiments.py`). They weren't in `app.py`'s reload list, so after a push the live site would have kept old copies. That's the same kind of bug that crashed the live site in November. A new test now fails if the site ever loads a `herding` module that isn't on the list. I checked that it really catches the problem by taking `calibrate` off the list for a moment.
